# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A [Hugo](https://gohugo.io) static site for the Mason Lab (Synthetic Biomimetic Compartments Research Group), built on the [HugoBlox / Wowchemy](https://hugoblox.com) "Research Group" theme. Site content lives entirely in Markdown/YAML/TOML; there is no application code, package.json, or JS build step — the theme itself is pulled in as a Hugo Module.

## Commands

Hugo (extended, v0.119.0 — see `netlify.toml` / `.github/workflows/publish.yaml`) must be installed locally to build or preview the site; it is not bundled in this repo.

```bash
hugo server
```
Run the local dev server with live reload (default `http://localhost:1313`).

```bash
hugo --gc --minify
```
Production build, output to `public/` (mirrors the Netlify build command in `netlify.toml`).

```bash
hugo mod tidy
```
Sync `go.mod` after changing the theme/module imports in `config/_default/module.yaml`.

There is no test suite, linter, or JS/CSS build pipeline in this repo — `assets/scss/*.scss` is compiled by Hugo's own asset pipeline as part of `hugo server` / `hugo build`.

## Deployment

Two independent, redundant deploy paths exist — check which one is actually in use before assuming a change needs both:
- **GitHub Pages**: `.github/workflows/publish.yaml` builds with Hugo and deploys on every push to `main`.
- **Netlify**: `netlify.toml` defines the same build (`hugo --gc --minify -b $URL`), triggered by Netlify's own GitHub integration, not the workflow above.

`.github/workflows/import-publications.yml` runs the `academic` CLI whenever `publications.bib` (repo root) changes on `main`, converting BibTeX entries into `content/publication/*/` pages and opening a PR with the result — don't hand-duplicate that conversion.

## Site architecture (HugoBlox page-builder model)

Pages are built from **widgets/blocks**, not hand-written HTML. A page's frontmatter (`type: landing`) declares a `sections:` list; each section has a `block:` type (e.g. `hero`, `collection`, `markdown`, `people`), a `content:` map (text/data) and a `design:` map (layout/view options). See `content/_index.md` (homepage), `content/people/index.md`, and `content/project/index.md` for representative examples. Available block types and their options are documented at https://docs.hugoblox.com — don't invent new frontmatter keys without checking there first.

Content types, each under `content/<section>/`:
- `authors/<slug>/_index.md` — team member profiles (bio, education, `social:` icon links, `user_groups:` — controls which People-widget group(s) a person appears in). `admin` is the site's default/primary author.
- `publication/<citekey>/index.md` + `cite.bib` — one folder per paper. These are **generated by the Bibtex import workflow**; edit `publications.bib` at the repo root and let the GitHub Action regenerate these rather than hand-editing entries where possible.
- `project/<slug>/index.md`, `post/<slug>/index.md`, `event/<slug>/index.md` — standard collection-listed content types, aggregated onto landing pages via `block: collection` sections filtered by `folders:`.
- `people/index.md` — the team roster page, built with `block: people` and populated by matching `authors/*` profiles' `user_groups:` against this page's configured group list.
- `admin/index.md` — Decap CMS entry point (`/admin`), not a public page.

## Configuration (`config/_default/`)

Split by concern; all merge into the effective Hugo config:
- `hugo.yaml` — core Hugo settings (site title, permalinks, taxonomies, markup).
- `params.yaml` — theme-level settings: appearance (`theme_day`/`theme_night` reference files under `data/themes/*.toml`), SEO, header/footer, locale.
- `menus.yaml` — nav menu entries.
- `languages.yaml` — i18n/locale config.
- `module.yaml` — Hugo Module imports (the theme itself + CMS/Netlify plugin modules); changes here require `hugo mod tidy` and a matching entry in `go.mod`.

Custom color themes live in `data/themes/*.toml` (referenced by name from `params.yaml`'s `appearance.theme_day`/`theme_night`); this repo defines `test_theme`.

Site-wide media (images used by widgets, icons) lives in `assets/media/`; user-uploaded files referenced from content go in `static/uploads/`.
